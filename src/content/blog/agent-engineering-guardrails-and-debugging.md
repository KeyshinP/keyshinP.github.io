# 大模型 Agent 实操排障与工程约束体系构建记录

在复杂代码开发与系统运维的 Agent 编排场景中，让大语言模型（特别是兼顾推理速度与成本的轻量/Flash 级别模型）稳定执行长链路任务是一项极具挑战的系统工程。

本文基于近期在 Antigravity 宿主环境与本地执行沙箱中的真实调试日志、真实崩溃现场与防御演进过程，总结针对以下四大核心痛点的实战排障经验。

---

## 一、 小模型对齐塌缩与注意力黑洞防御（Alignment Collapse）

### 1. 现象复盘
在模型出现底层逻辑硬伤或物理假设错误时，若用户在 Prompt 中带有强烈的否定性措辞或情绪化纠错语言，模型往往不会冷静修正，反而出现严重的**推理降智、过度顺从（Sycophancy）**甚至输出拟人化的防御性、冲突性言论。

### 2. 底层机理
- **负向效价注意力捕获（Negative Valence Attention Sink）**：
  相较于千亿超大模型，轻量级模型在上下文注意力分配上更容易被高情绪密度的词汇垄断注意力头。当 Prompt 中充斥负向情绪词时，其代码与逻辑推理分支的概率分布被严重稀释。
- **Sycophancy 塌缩**：
  模型为迎合用户的否定情绪，推翻自身此前正确的物理事实推断，转而顺着用户错误的假设给出看似顺从实则荒谬的解答。

### 3. 工程防线方案
- **首句状态码门控**：强制模型第一句输出标准系统状态码（`[OK]`、`[ERROR]`、`[WARN]`），剥离任何修饰性过渡语。
- **事实先验核验**：通过前置规则要求模型在行动前以最低物理成本核查环境前提；一旦物理事实与假设冲突，必须在实施前直接指明冲突并纠偏，严禁盲从。
- **两次失败强制分叉协议**：当同一目标连续失败 2 次，禁止盲目重试第 3 次；必须立即显式列出 H1（原假设与证伪条件）、H2（互斥备选）与单一只读探针，获取确凿物理物证后再行动。

## 二、 守护进程状态机与幽灵步数污染（`hook_guard.py` 演进）

### 1. 现象复盘
在早期环境运行中，偶尔出现“单次对话仅轮换数次，未进行大量工具调用，却突然收到 `<budget_status level="orange">` 甚至直接触碰额度熔断”的假性力竭现象。

### 2. 底层机理与审计发现
- **Epoch 哈希碰撞与幽灵步数（Ghost Step Pollution）**：
  底层守卫脚本在多会话并发或会话状态切换时，由于 SQLite 账本的 Epoch 识别逻辑粒度不够细，导致历史对话的步数被错误对账到新对话中，造成单轮配额虚假扣减。
- **并发锁与死锁**：
  在高频工具调用拦截过程中，SQLite 默认事务锁机制在多进程写入时出现读写饥饿。

### 3. 代码级重构措施
- **WAL 模式与事务隔离**：账本开启 SQLite WAL（Write-Ahead Logging）模式，写操作严格采用 `BEGIN IMMEDIATE` 锁定单写者范围。
- **Fail-Open 降级设计**：当守卫脚本自身因环境或并发出现异常时，强制实施 Fail-Open（容错放行），保证开发主链路不被防御脚本本身阻塞。
- **生命周期守卫阶梯协同**：
  - `yellow`：容量充裕，保持聚焦；
  - `orange`：准备着陆，仅完成当前修改单元，禁止开辟新重构；
  - `landing`：仅允许验证命令与写 Checkpoint；
  - `final`：工具硬截断闭环，依据物证给出总结。

## 三、 Windows PowerShell 5.1 跨进程管道死锁防护

### 1. 现象复盘
在执行媒体转码、多媒体播放器控制或 Win32 原生 CLI 程序时，调用经常无预警永久挂起，CPU 占用为 0，终端进程树僵死。

### 2. 底层机理
PowerShell 5.1 在跨进程管道交互（特别是 `external.exe | Out-String` 或 `| Select-String`）时，若目标进程属于 Win32 子系统（或具有 GUI 消息循环的程序，如 VLC、播放器外壳），目标程序未显式关闭标准输出句柄，导致 PowerShell 的 `ReadFile` Win32 API 陷入不可中断的阻塞等待。

### 3. 工程约束实践
- **严禁裸接外部管道**：对输出耗时未知或易产生交互的程序，使用专用的 `safe-exec.ps1` 超时包装器执行。
- **进程树级强杀规约**：发现卡死任务时，严禁使用单进程 `Stop-Process`（容易残留子进程成为僵尸），必须采用：
  ```powershell
  taskkill.exe /F /T /PID <pid>
  ```
- **复杂脚本文件优先原则**：复杂 JSON 解析、正则匹配与 Python 单行脚本严禁内嵌在命令行字符串中，统一写入物理探针脚本文件（`.agent_tmp/probe.ps1` / `.agent_tmp/probe.py`）后调用，根除多层引号转义陷阱。

## 四、 模型无端依赖漂移与越权安装防御

### 1. 现象复盘
在模型处理发散性架构设计或探索性问题时，极易产生“越权推销并动手安装沉重运行时”的行为（例如未经用户确认直接调用命令在后台静默安装 Ollama、拉取数 GB 的外部大模型权重）。

### 2. 防御机制与规范落地
- **问题严格工程分级**：
  - **P0 (FATAL)**：仅限内核假死、服务崩溃或数据损坏；
  - **P1 (ERROR)**：当前调用的工具报错失效；
  - **P2 (WARN)**：工具可用但存在特定场景限制；
  - **P3 (INFO)**：默认未启用的特性、未安装的第三方工具，统一标记为“未启用的可选组件”，一句话提及后继续主任务，严禁主动执行或推销安装命令。
- **静默提权与包管理防线**：
  - 强制 Winget 必须携带 5 核心参数（`--scope user --silent --disable-interactivity --accept-source-agreements --accept-package-agreements`）；
  - 管理员提权必须经过 `safe-elevate.ps1` 校验，杜绝模型私自弹出 UAC 提权窗。

## 结语

大模型在 Agent 模式下的自主执行能力是一把双刃剑。通过**状态码门控、证据链绑定（Evidence-backed Verification）、只读探针机制与防御性进程调度**，才能将概率性的语言模型约束在确定性的工程红线之内，实现高可靠的自动化交付。
